# 发稿台稿本

本机发稿台列出 `novel/` 下带 `书资料.yml` 的稿本，允许按作品名称新增空稿本，并在设置页补齐创建平台作品所需的书资料字段。稿本身份是目录名；列表标题和认领用书资料里的作品名称。

## 列表

只扫描 `novel/` 的直接子目录。目录内有 `书资料.yml` 才进列表。没有章节文件仍进列表，章节数为 0，不标加载错误。没有 `novel/` 时列表为空，并提供添加表单。

Scenario: 发稿台列出带书资料的稿本

- 给定 `novel/已有书/书资料.yml` 且其中有章节文件
- 当打开 `/publish`
- 那么列表出现该稿本，能发稿、干跑、绑定、打开设置

Scenario: 没有章节的稿本仍出现在列表

- 给定 `novel/空书/书资料.yml` 且目录内没有「第{序号}章-」文件
- 当打开 `/publish`
- 那么列表出现该稿本，章节数为 0，不是加载错误，仍可打开设置、点发稿或创建平台作品

## 添加稿本

发稿台提供添加表单，只填作品名称。提交后：

1. 去掉首尾空白；空名称、或名称含 `/` `\` 则拒绝，不写磁盘。
2. 以作品名称为目录名，在 `novel/` 下创建目录（没有 `novel/` 则先建）。
3. 目录已存在则拒绝，不覆盖。
4. 写入 `书资料.yml`，`作品名称` 为提交值；其它书资料键可空。不要求章节文件，不跑 CLI `init` 的大纲灌入。
5. 成功则重定向到 `/publish`，列表能看见新稿本。

CLI `python -m publish init` 仍要求目录已存在且已有章节文件。

Scenario: 按作品名称新增空稿本

- 给定发稿台，且 `novel/` 下没有同名目录
- 当提交作品名称「新书」
- 那么出现 `novel/新书/书资料.yml`，其中作品名称为「新书」；响应回到 `/publish`，列表可见「新书」，章节数为 0

Scenario: 非法或冲突的名称不建稿本

- 给定已有 `novel/已有书/`
- 当提交空白名称、或「a/b」、或「已有书」
- 那么不新建目录或书资料，页面留在发稿台并显示错误

## 设置

设置页继续改绑定作品 ID、章节可见性、发稿时刻、单次章数上限、连载状态、章间隔秒、人工等待秒。本次增加：作品名称、频道、分类、简介、封面上传。

保存规则：

- 作品名称不能为空；只写书资料，不重命名目录。
- 频道、分类、简介按文本写入对应书资料键；空字符串表示空键，不在这次保存里去清空远端。
- 上传封面时，文件写进该稿本目录，书资料「封面」写成该相对文件名；未上传则不动已有封面。
- 不提供标签、子分类编辑。
- 正在发稿的稿本锁定设置。

Scenario: 设置页写入创建必填和封面

- 给定稿本目录名为「空书」，设置页打开
- 当把作品名称改为「空书新名」，填写频道、分类、简介，并上传封面文件后保存
- 那么书资料含这些值，封面文件在 `novel/空书/` 内，「封面」键指向该文件；目录名仍是「空书」；响应表示已保存

## 发稿入口

每个可加载稿本保留「发稿」「干跑」「绑定」「设置」。创建平台作品的入口见 `publish-create`：文案为「创建平台作品」，不再使用「搜不到再创建」。

Scenario: 发稿主按钮不带创建许可

- 给定列表中有一份可加载稿本
- 当查看该稿本的操作
- 那么主按钮文案为「发稿」，另有「创建平台作品」；页面不出现「搜不到再创建」
