# 一次发稿只读一次后台目录

水位（ADR 0011）原本读两次：算计划读一次，执行章节动作时再读一次，然后拿计划里的章 ID 去第二份结果里找。两次之间任何差异都会让计划落空——而 `list_remote_chapters` 对「草稿箱」标签是静默容错的，点不开就当没有草稿。结果是第二次少读了草稿箱，整批「改可见性」动作全部落到「找不到要更新的草稿第N章」，一次能停掉十几章。

决定：一次发稿只读一次后台目录，计划和执行共用同一份远端观察。「章节管理」和「草稿箱」都是水位与可见性的必要来源，任一个在等待窗口内打不开就停机并说明是哪个，不再静默返回一份缺章的目录。计划里的章在这份观察中找不到时仍然停机并指名章号——那是真实不一致，不是可以跳过的噪声。

读不全有四种形态，都要挡住：草稿箱标签点不开；目录行还没渲染就开始数；换标签后数到的还是上一个标签留在 DOM 里的旧行；以及水位够不到章缓存里最大的已建章。最后一条是兜底——前三条都可能只让目录少一截而不是全空，而水位偏低的后果是把后台已经有的章重新建一遍。它只看章缓存和远端观察，是纯决策，放在 `plan.py`。后台确实删过章时，按本 ADR 之前的 0011 改绑一次清掉章缓存即可解开。

例外只有一个：章缓存里没有任何章 ID、章节管理也一行都没读到的空新书，没有东西可丢，草稿箱缺失按没有草稿处理，否则刚创建的平台作品发不出第一章。

配套：章写成功后立刻落盘再回目录；章 ID 在进入编辑页、云端存稿之后、提交之后各取一次，取先到的非空值。新建章节进入编辑页时地址是 `publish/?enter_from=newchapter`，还没有章 ID——后台第一次云端存稿才分配并写回地址栏，而定时发布提交后页面又会跳走。只取一次，新建的章就永远记不下章 ID。

目录观察的范围只有作家后台当前选中的那一卷。列表按分卷过滤，一次只显示一卷；行本身还是虚拟滚动的，滚出视口就被移出 DOM，所以要边滚边收，不能滚到底再取一次快照。即便如此，多卷作品仍读不到整本——《工牌不认婚约》12 卷，第 1–20 章在别的卷里怎么滚都读不到。

因此「本地有而目录里没有」推不出「后台缺这一章」，水位之内的缺口既不补发也不据此停机。要做跨卷缺口检测，得先让目录遍历分卷；那是另一个决策。

**Status**: accepted

**Considered Options**: 保留二次读取但找不到时只记报告跳过（会静默漏发章）；草稿箱继续静默容错但执行前比对两次读取的差异（多一次读取仍要停机，没有省事）；水位校验只挡「目录全空」（挡不住读到一半，而读到一半会直接重复建章）。

**Consequences**: 水位之上、章缓存里带章 ID 的章，现在一律判成「目录没读全」并停机，所以绝大多数路径不再产出 `更新草稿`。仅剩一条：`_match_remote_chapter` 的标题兜底会匹配「标题里没有第N章」的目录行，这类行不进水位计算，于是本地章号可以大于水位却仍匹配到远端行。`ACTION_UPDATE_DRAFT` 因此保留。

新建章节还要确认真的进了新章页：新章页的地址不带章 ID。导航超时后兜底去点「创建章节」，点击没生效时页面仍停在上一章的编辑器上——那里同样有标题框、地址同样含 `/publish/`——继续写就是拿这一章的正文覆盖上一章。这已经在真实发稿中发生过一次：第 7、8 章缓存到同一个章 ID 而正文指纹不同。
