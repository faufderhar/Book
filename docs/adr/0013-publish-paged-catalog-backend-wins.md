# 逐页读全后台目录，读全之后以后台为准

ADR 0012 把目录当成虚拟滚动的长列表，边滚边收，滚不动了就算读完。那个判断是错的：作家后台的章节目录是**每页 15 行、按章号倒序的分页表格**。一页之内的行全部挂在 DOM 上，滚动收不出第二页；页码控件晚渲染一拍，`scroll_and_collect` 就只收到第一页那 15 行。93 章的书读成 15 章，缺口检测把早已发布的章判成缺口，重新建一遍。

决定：**逐页遍历**。当前标签的每一页都翻一遍，行并起来；读全整本靠翻页，不靠滚动。任何一页读不出来都停机，并**指名是第几页**，不得当成「那几页没有章」——把没读到的页当成空页，就会拿一份缺章的目录去判后台缺哪些章。

三种读不全的形态各自停机：页码控件有、却一章都没读到（分页说明这个标签下有内容，读不到就是没渲染出来）；点了页码翻不过去；翻过去了但那一页的行在等待窗口内没换成新行。翻页不改地址，页码亮了不等于新行已经渲染出来——只等「有行」会把上一页还挂着的行再收一遍，真正这一页的章就丢了。

还有一种是「翻过去了、也读到了行，但没读全那一页」。除最后一页外，每页的行数都该等于页容量，少了就是那一页没读全。页容量不写死 15，取各页里最多的那个——后台改每页条数也不会误报；只有最末一页可以不满，那是余数。

单个标签为空是合法的：章可以全在草稿箱里，章节管理就空着；没有草稿时草稿箱也空着。两个标签都空、而章缓存记着建过章，才是异常。

收行要按**视口水平位置**过滤。两个标签的面板长期共存于 DOM，切走的那个并没有消失——它被挪到视口左侧之外，仍然是显示状态、仍然有宽高。只按宽高判可见，会把「章节管理」当前页的行收进草稿箱那一趟，还被强制标成草稿。

**只支持单卷作品**。卷选择器里多于一个卷直接停机，不得只读当前那一卷。ADR 0012 承认过多卷读不到整本（《工牌不认婚约》12 卷，第 1–20 章在别的卷里怎么滚都读不到），当时的处置是「水位之内的缺口既不补发也不据此停机」。那是在读不全的前提下的将就。现在单卷能读全了，就不再用一份注定残缺的观察去做决策——多卷直接停，等到目录遍历支持分卷再说。

整本读全之后，**以后台为准**：

- 后台有、章缓存却缺章 ID 的，回填进书资料。先落盘再动笔：这一趟即使后面停机，这些 ID 也不会再丢一次。
- 本地有、后台没有的**末尾缺口**补建，不再受 ADR 0011「只补水位之后」的限制。水位是读不全时代的保守线；读全了就知道后台到底缺哪几章，没必要再让水位挡住。
- **中间缺口只报告，不补**。后台只能末尾追加，把中间缺的章补进去，顺序会乱。

没读全时退回旧兜底：水位够不到章缓存里最大的已建章就停机（ADR 0012 的第四种形态）。这条由 `RemoteObservation.catalog_complete` 分流——读全与没读全走两套判断，不混。

**Status**: accepted

**Supersedes**: [0012](./0012-publish-single-catalog-observation.md) 的第 13–15 段（目录是虚拟滚动、边滚边收、多卷时水位之内的缺口不据此停机）。0012 的其余部分——一次发稿只读一次目录、两个标签都是必要来源、章写成功后先落盘再回目录、新建章节必须确认进了新章页——全部仍然有效。

**Considered Options**: 继续滚动收行但把等待窗口拉长（页数多时仍然只能收到当前页，拉多久都没用）；只读第一页并靠水位兜底（目录按章号倒序，第一页确实是最高的那些章，水位是对的，但缺口检测拿不到全量，中间缺口全部误判）；多卷时只读当前卷并把别卷的章当成「不在本次范围」（读到的观察和「整本」不是一回事，任何以它为准的决策都是错的）。

**Consequences**: 分页控件晚渲染一拍、只读到第一页，仍然是这里最大的残余风险。它被下游兜住了：目录按章号倒序，第一页是最高的那些章，所以水位取自第一页，漏掉的章必然落在水位之下——`plan.py` 会把它们判成中间缺口而停机，进不了补建路径。

多卷作品从此完全发不了，直到目录遍历支持分卷。这是有意的：发错一章的代价高于发不出。
