# 需求

## 用户与主循环

作者或工作室用来选题材。看各正版平台哪些分类在进榜、哪些在掉、有总榜时某分类占了多少坑。不是读者站，不是作家助手，不是对外 SaaS。

v1 门禁：番茄公开榜能每日入库并算出热度，本机看板能看摘要和下钻。起点、七猫、晋江、掌阅是产品范围，按序后加，不是同一天上线条件。

## 快照契约

一份快照 = 自然日 + 平台 + 榜单 ID 的完整名次，最多 100 条。同一天同一榜再写入则整份覆盖。

每条名次：

- `rank`
- `platform_work_id`
- `title`
- `author`
- `platform_category`
- `serial_status`（页面有则记）
- 头部指标（番茄 = 在读人数）
- 页面上的最近更新时间（有则记）

不存正文。作品身份 = 平台 + 该平台作品 ID。分类用该平台原名，不映射。

## 热度

- 占位只在总榜上按作品分类统计 TopN 条数和平均名次。番茄官网只有分类阅读榜 / 新书榜，故番茄 v1 不算占位。
- 分类榜只算新进、掉出，并展示该榜头部指标。
- 新进 / 掉出对比上一个自然日的有效快照。没有昨日快照则不计算进出，不显示成零。
- 失败的榜当天没有快照，看板标红：「当天无有效快照，进出不计算」。

## 采集

- 只请求公开榜单。番茄：`https://fanqienovel.com/rank/{频道}_{榜种}_{分类}` 取目录与字体，`/api/rank/category/list` 取最多 100 条（官网分页同一接口）。
- 限速。HTTP 403 / 风控：该平台停止当日剩余采集，看板标红。
- 番茄书名 / 作者有字体替换：用页面下发的字体把可见文字还原出来，不升级成对抗系统。
- 不登录、不打码、不走代理池、不抓章节。

## 番茄验收

- 热度计算有不依赖网络的夹具测试。
- 连续两天成功快照后，分类榜能看到新进 / 掉出。
- 失败的榜不出现伪造进出。
- 每天 15:30（`Asia/Shanghai`）跑一次即可。番茄榜单每天下午 3 点前更新昨日数据。

cron 示例（本机）：

```
30 15 * * * cd /Users/guxiaobin/project/Book && .venv/bin/python -m book.cli crawl fanqie
```

看板也可点「同步榜单」手动采一次，效果与上面的 CLI 相同。

## 后续平台

每个适配器只做「公开页 → 同一快照契约」。顺序：起点 → 七猫 → 晋江 → 掌阅。

## 不做

- 笔趣阁及任何盗版聚合
- 登录作家后台 / 未上榜作品
- 跨平台合并作品或统一题材树
- 爆款预测、稿费或收入估算
- 代理池、打码、登录、对抗 WAF
- 小时级采集、失败用旧日数据顶上
- 微信读书 / QQ 阅读
- 正文 / 章节
